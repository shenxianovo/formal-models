# 个人数字环境

## 1. 目标与范围

个人数字环境是一个人持续访问和管理信息、参与协作、开展数字活动的环境。终端、应用、自动化程序、Agent、计算节点和存储服务都是其中的组成部分。

本文件规定这个环境的目标、概念和约束，不规定具体产品、协议、部署方式或服务数量。

其目标是：**在设备、软件和执行环境发生更替时，保留必要的信息与活动状态，使个人能够在自身权限范围内持续使用、管理和委托这些资源。**

这里的个人控制有明确边界：个人能够管理自己的资源与授权；共享资源遵守协作规则；外部服务中的资源遵守该服务的权限与业务规则。

## 2. 基本区分

### 2.1 交互与执行

终端提供输入、输出及必要的本地处理。执行环境运行程序、使用工具并实施操作。

发出请求的终端与执行请求的环境可以位于不同设备。执行过程的生命周期不应由发起请求的网络连接决定。

终端断开仅表示该连接中断，不表示活动已经完成、失败或取消。

### 2.2 持久状态与运行状态

持久状态是按保留要求保存、用于后续访问和恢复的信息。运行状态是某次执行中的进程、内存、连接及其他现场状态。

需要跨越进程生命周期保留的信息，应进入持久状态。恢复以已保存的信息为依据；未保存的运行状态不属于恢复保证。

存储与计算是不同职责，可以部署在同一设备，也可以分开部署。职责分离不要求物理分离。

### 2.3 资源、操作与活动

**资源**是可被识别、访问或管理的对象，例如文档、项目资料、日程和文件。

**操作**是对资源或外部系统实施的一次动作，例如读取、修改、发送和确认。

**活动**是需要被持续识别和管理的过程，可以包含多次操作、多个参与者及多次执行。

资源不需要依附于任务才能存在。活动也不等同于某次程序运行。

### 2.4 软件与信息

应用、自动化程序和 Agent 是使用信息、实施操作的参与者。

需要在软件替换后继续使用的信息，其持久化表示、必要语义和访问方式应能够独立于该软件保留。模型上下文与聊天会话不是长期个人信息的唯一载体。

## 3. 信息与权威边界

### 3.1 状态由相应的权威规则确认

资源的有效状态由对该资源有权作出确认的主体或协作规则决定。

| 资源范围 | 状态确认依据 |
| --- | --- |
| 个人控制的资源 | 个人设定的管理与提交规则 |
| 共同管理的资源 | 参与者采用的协作与并发规则 |
| 外部服务管理的资源 | 相应服务的业务规则与确认结果 |

权威表示有权确认业务状态，不表示其中的所有信息都必然符合现实。

个人环境中保存的副本、引用、缓存和索引，不因被保存到本地而获得对原资源的控制权。本地修改外部操作的状态记录，也不等于该操作已在外部系统生效。

### 3.2 保留理解信息所需的语义

需要长期使用的信息，应连同必要的结构、来源和解释方式保存。涉及版本、同步或并发修改时，应能够识别所依据的版本或状态。

原始材料、人的明确陈述、观测记录和模型推断具有不同来源与含义，应能够区分。模型推断被保存，不等于它已经被确认。

摘要、索引等派生表示应与其依据的信息保持可识别的关系。需要保留的原始材料，不应仅因产生了派生表示而被隐式替换。

### 3.3 统一使用不要求统一存储

不同资源可以采用不同存储系统和访问方式。对外部资源，可以保存引用、来源和必要的已知状态，而不取得其权威副本。

统一使用的基础是能够识别资源、理解必要语义，并遵守相应的访问和操作规则；不是将全部数据搬入一个数据库。

## 4. 身份、授权与委托

### 4.1 身份与权限分别处理

身份用于识别参与者；授权用于规定参与者在什么条件下可以对哪些资源执行哪些操作。

一个人可以在不同情境中使用不同身份。身份之间的关联、信息共享和权限继承应由明确规则决定，不能因属于同一个人而默认打通。

### 4.2 委托具有边界

程序代表个人实施操作时，应能够确定委托来源及授权范围，包括允许访问的资源、允许执行的操作和适用条件。

委托不能超出委托方有权授予的范围。Agent 提出的计划、生成的文字和自行声明的角色，都不能代替有效授权。

权限边界由实际控制资源或操作的机制执行，不能仅依赖 Agent 遵守提示词。

### 4.3 撤销与恢复

授权应有明确的撤销方式、生效规则和在途操作处理规则。

撤销约束生效后的访问与操作，不自动收回已交付的信息，也不自动撤回已经完成的外部行为。

身份恢复、数据恢复和授权恢复是不同问题。恢复流程应在重新建立控制权的同时，按照明确规则处理旧设备和旧凭据的访问资格。

## 5. 多种参与方式

### 5.1 共享资源语义与业务规则

人可以通过界面操作，程序可以调用接口，自动化机制可以响应事件，Agent 可以根据上下文提出或实施操作。

不同入口可以采用不同交互形式，但对同一逻辑资源的操作应遵守一致的资源语义、权限约束和业务规则。

不同参与者的授权范围可以不同。入口相同不表示权限相同，入口不同也不应产生彼此矛盾的业务状态。

### 5.2 Agent 的位置

Agent 是能够根据目标与上下文选择行动的软件参与者。它在授权范围内获取信息、使用能力并提交结果。

Agent 不拥有独立于授权体系的权限，也不构成个人数字环境的唯一入口。个人可以直接操作资源，也可以使用普通应用或确定性自动化程序。

需要长期保留的资源、活动状态和结果，不应随某个 Agent 实例或会话的结束而消失。

## 6. 活动与执行

### 6.1 持续活动需要持久记录

对需要跨连接、跨进程持续的活动，应保存足以识别、查询和恢复该活动的必要信息。

系统向用户确认此类活动已被持久接收时，其必要记录应已完成持久化。记录的内容由活动的恢复要求决定，不要求保存全部运行现场。

### 6.2 活动与执行尝试分开

一次活动可以经历多次执行尝试。执行尝试可以中断、失效或被替换，而活动继续存在。

执行者失去响应，不等于活动从未产生效果。恢复与重新分配需要依据已保存状态，并处理旧执行者继续运行的情况。

谁有权继续执行、哪些结果可以被接受，应有明确的协调与提交规则。

### 6.3 重试遵守操作语义

可重复计算、可去重操作和不可安全重复的外部行为，需要分别处理。

未收到外部回执，只能说明结果尚未得到确认，不能直接推导为外部操作未执行。重试前应根据相应服务的确认、查询或去重机制判断。

活动的完成由其完成条件及相应证据确认。程序退出、文本声称成功和外部业务完成是不同事实。

## 7. 工作区与结果提交

工作区是执行过程中使用的输入视图、临时状态和未提交改动的集合。

对于基于文件或版本化数据的修改，工作区与权威资源之间遵守以下约束：

1. 执行所依据的输入应能够被识别；需要版本一致性时，记录相应版本。
2. 工作区中的修改通过资源规定的提交机制生效，并遵守其权限与并发规则。
3. 需要保留的中间状态和结果，在清理临时工作区前完成相应持久化。

并发修改的接受、覆盖或合并，应依据原资源的冲突处理规则确认。完成先后本身不自动构成覆盖其他修改的授权。

工作区处理的是执行现场与数据修改。发送消息、确认预约等外部操作，按照对应系统的业务语义生效，不能统一解释为工作区结束时的一次文件同步。

计算节点的可替换性以必要状态已被持久化、替代节点具备所需能力为前提。它不等于任意运行进程可以无损迁移。

## 8. 控制职责

控制职责是维持访问、活动与执行规则的机制，包括识别请求者、检查授权、记录必要状态、协调执行资格、接受有效结果和处理撤销。

这些职责与 Agent 的任务推理分开：Agent 选择或提出行动，控制机制根据明确规则决定哪些行为与结果可以被接受。需要人的判断时，由指定的人作出确认。

控制职责不要求集中在一个服务中。个人侧与外部服务侧分别执行各自的权限和业务规则；个人侧的允许不能代替外部服务的允许。

执行分配、任务队列和工作区管理属于支持活动的机制，不决定整个环境必须以任务或 Agent 为中心。

## 9. 连续性与可替换性

### 9.1 替换保留受管理的持久状态

更换终端、应用、Agent 或计算节点时，应能够按既定访问与恢复规则继续使用需要保留的信息。

这种连续性依赖可用的数据表示、必要语义、访问能力及恢复材料，不依赖旧软件持续运行。

### 9.2 联网与离线能力有明确边界

终端能够离线执行什么，取决于已有数据、本地能力及适用的离线授权规则。

需要外部系统确认的操作，在取得确认前保留相应的未确认状态。远程执行能力不能替代断网时不存在的连接。

### 9.3 保留与删除受规则约束

个人可以在自身管理权限内决定信息的采集、保留、共享和删除规则。

同步、备份、缓存与外部副本具有不同的保留边界。某处删除成功，不等于所有副本都已删除；系统的说明应与实际可控制的范围一致。

## 10. 基础能力

上述约束对应以下基础能力。它们是职责划分，不是固定的组件清单。

| 基础能力 | 负责的问题 |
| --- | --- |
| 身份、授权与恢复 | 谁在参与，可以做什么，如何撤销及恢复控制 |
| 持久信息与互操作 | 信息如何保存、理解、引用和迁移 |
| 资源访问与操作 | 不同参与者如何按同一资源规则开展工作 |
| 活动与执行保障 | 需要持续的过程如何被记录、协调、恢复和确认 |
| 多端交互与状态同步 | 不同终端如何接入，并表达各自可用的数据与能力 |

**个人数字环境的持续主体是人；需要延续的是受管理的信息、关系与活动。设备、应用、Agent、计算和存储都是实现这些目标的组成部分。**
